# LocardX Forensic File Recovery & Evidential Carving Methodology
**Module Specification -- Step 12 (Pillar 3)**

---

## 1. Overview & Forensic Objectives

The LocardX File Recovery Module constitutes the primary evidential recovery pillar of the platform. Its explicit objective is to extract deleted, corrupted, or unreferenced files from raw bitstream storage images produced by **Step 11 -- Forensic Disk Imaging / Acquisition** without modifying the source evidence or fabricating missing data.

```
Physical Storage Device
         |
         v
[Step 11: Forensic Disk Acquisition]
         | (Streamed SHA-256 Bitstream Acquisition)
         v
AcquisitionArtifact (.raw / .dd)
         |
         v
[Step 12: Advanced Recovery Pipeline]
  |-- Phase 1: Pre-Flight Image Validation & Integrity Check
  |-- Phase 2: Partition & Filesystem Metadata Inspection (TSK / Pure Rust)
  |-- Phase 3: Sliding-Window Signature & Structure-Aware Carving
  |-- Phase 4: Cluster-Aligned Fragment Reconstruction (No Data Fabrication)
  |-- Phase 5: Deterministic Evidence-Factor Confidence Scoring
  |-- Phase 6: Non-Destructive Isolated File Export
  `-- Phase 7: SQLite Persistence (011_recovery.sql) & Hash-Chained Audit Logging
```

## 2. Evidential Input Handoff & Fail-Closed Validation

The Recovery Module strictly consumes `AcquisitionArtifact` structures generated by the Acquisition layer:

```rust
pub struct AcquisitionArtifact {
    pub acquisition_id: String,
    pub image_path: String,
    pub image_format: String,
    pub image_size_bytes: u64,
    pub image_sha256: String,
    pub source_device_snapshot: AcquisitionDeviceSnapshot,
    pub acquisition_timestamp: String,
    pub is_verified: bool,
    pub audit_reference: String,
}
```

### Pre-Flight Verification Rules (Fail-Closed)
Before any scanning or parsing begins, the engine performs strict pre-flight verification:
1. **Verification Status**: `artifact.is_verified` must be `true`; unverified acquisitions are rejected immediately with `RecoveryFailureReason::IncompleteAcquisition`.
2. **Format Compatibility**: Only `raw` and `dd` image formats are accepted; VMDK/VHD/compressed images are rejected with `RecoveryFailureReason::InvalidFormat`.
3. **File Existence**: The image path must exist on disk (`RecoveryFailureReason::ImageNotFound`).
4. **Size Validation**: The actual file size on disk must exactly match `image_size_bytes` (`RecoveryFailureReason::SizeMismatch`).
5. **Streaming SHA-256 Re-Verification**: The image is streamed in 1 MiB chunks and hashed with SHA-256. If the calculated digest differs from `artifact.image_sha256`, the operation fails closed with `RecoveryFailureReason::HashMismatch` to prevent tampering.

## 3. Recovery Modes & Execution Strategies

Operators can select among three distinct recovery modes:

| Recovery Mode | Description | Primary Use Case |
| :--- | :--- | :--- |
| **All** (Default) | Executes filesystem inspection first, then slides carving across all unallocated / remaining image sectors | Comprehensive investigation of active or deleted data |
| **Filesystem Only** | Inspects partition tables, NTFS MFT records, and FAT32 directory tables for deleted entries | Fast extraction when filesystem structures remain intact |
| **Carving Only** | Bypasses filesystem structures and directly scans raw sectors using signature and structure parsers | Severely corrupted, reformatted, or wiped file systems |

---

## 4. Evidential Preservation Guarantee

1. **Zero Write Operations**: The source evidence image is opened strictly read-only (`File::open`).
2. **Path Collision Prevention**: The engine validates that `output_directory` does not collide with or point to the evidence image itself.
3. **Separate Export Directory**: Recovered files are written exclusively to the operator's designated output directory, organized into category subfolders (`images/`, `documents/`, `archives/`, `databases/`, `text_files/`).
4. **Cryptographic SHA-256 per File**: Every extracted candidate is independently hashed with SHA-256 upon recovery, ensuring an unbroken chain of custody.
