1. CRITICAL STACK OVERFLOW (0xc00000fd) - RESOLVED
--------------------------------------------------------------------------------
[CRASH LOCATION 1]: crates/acquisition/src/artifact.rs:66
[CRASH LOCATION 2]: crates/recovery-engine/src/source.rs:97
Triggered by: "Verify Image Disk Integrity On-Demand" (Acquisition Artifact Verification)

Root Cause:
- In Windows PE binaries, default thread stack allocation is 1,048,576 bytes (1 MiB).
- `verify_integrity()` declared:
    let mut buffer = [0u8; 1024 * 1024];
- This allocated an entire 1 MiB fixed array directly onto the active call stack frame.
- When dispatched through Tauri IPC / Tokio runtime, active stack frames pushed the stack pointer
  past the 1 MiB guard page, instantly triggering STATUS_STACK_OVERFLOW (0xc00000fd) and killing
  the main thread.

Resolution Applied:
- Replaced stack allocation `[0u8; 1024 * 1024]` with heap allocation `vec![0u8; 1024 * 1024]`.
- Call stack frame footprint reduced from ~1,048,576 bytes to 24 bytes (standard fat pointer).
